BlockEditor 块编辑器

核心组件

完整的类 Notion 编辑体验：块选择、拖拽排序、缩进、Slash 菜单、快捷格式、撤销重做和文件插入。

主要 Props

v-model
TiptapDocumentJson 文档内容
readonly
只读模式
features
禁用块、隐藏块、禁用渲染器
documentId
内部文档链接和 Agent 上下文

主要暴露方法

getJSON / getText
读取当前内容
getSelectedBlocks
读取选中块
insertMarkdown
插入 Markdown
replaceBlocksWithMarkdown
校验后替换连续块
使用接口插槽与组合
打开真实示例 ↗

基础用法

通过 v-model 绑定 TiptapDocumentJson。组件会自动初始化块 ID，并提供编辑、选择、拖拽、Slash 命令和历史记录。

在线预览 ↗
BlockEditor.vue
<EditorProvider>
  <BlockEditor
    v-model="content"
    :readonly="false"
    :features="{ disabledBlocks: ['mathBlock'] }"
    @text-update="handleTextUpdate"
  />
</EditorProvider>

接口

Props类型默认值说明
modelValueTiptapDocumentJsonundefinedv-model 文档内容
readonlybooleanfalse禁用编辑交互
settingsAppSettingsDEFAULT_APP_SETTINGS编辑器宽度、字号、快捷键等
featuresEditorFeatureOptions{}禁用块、隐藏块和自定义 Slash 菜单
pluginsEditorPlugin[][]注册自定义块插件
documentIdstring''内部文档链接和 Agent 上下文

Events

update:modelValue内容 JSON 发生变化时触发textUpdate纯文本变化时触发，适合更新搜索索引ready / destroy编辑器实例创建和销毁openDocument点击内部文档链接，参数为 documentId、blockId

Expose

getJSON()getText()getSelectedBlocks()insertMarkdown()replaceBlocksWithMarkdown()focus()undo()redo()

插槽与组合

BlockEditor 本身没有公开内容插槽，工具栏和上下文菜单由编辑器内部管理。需要替换交互层时，使用 features.slashMenuComponent、features.slashMenuProps，或组合导出的 EditorBubbleMenu、EditorContextMenu。

NButton / NButtonGroup →SlashCommandMenu →EditorContextMenu →

BlockRenderer 块渲染器

使用同一套文档 JSON 进行只读展示，支持内部文档链接和渲染器开关，不发出内容更新事件。

i适合预览页、搜索结果、分享页面和服务端渲染场景。
使用接口插槽与组合
打开真实示例 ↗

基础用法

把与编辑器相同的 JSON 传给 BlockRenderer，即可在预览、分享或搜索结果页面中只读渲染。

在线预览 ↗
RendererPage.vue
<BlockRenderer
  :content="content"
  :features="{ disabledRenderers: ['mathBlock'] }"
  @open-document="openDocument"
/>

接口

Props类型说明
contentTiptapDocumentJson待渲染的文档内容
featuresEditorFeatureOptions控制隐藏块和禁用内置渲染器
renderersRecord<string, Component>按 block ID 或 node type 覆盖渲染器
pluginsEditorPlugin[]与编辑器共享插件注册表

Events

openDocument内部链接点击事件，参数为 documentId、blockId

插槽与组合

BlockRenderer 没有公开插槽。通过 renderers 注入自定义 readonlyView，组件会把 node、attrs、content 和 readonly 传给自定义组件。

  @rename="renameDocument"
/>

接口

Props类型说明
nodesSidebarDocumentNode[]buildSidebarDocumentForest 的树节点
currentDocumentIdDocumentId当前高亮文档
collapsedDocumentIdsSet<DocumentId>需要收起的节点集合
draggedArticleIdDocumentId | null拖拽中的文章 ID
busyboolean保存期间禁用选择

Events

select / toggle选择文档、展开或收起节点createChild请求在指定文档下新建子页面properties / rename / delete属性、重命名和删除操作dragStart / dragEnd拖拽生命周期，宿主负责排序持久化

插槽与组合

DocumentTree 本身没有插槽。每个节点由 DocumentTreeNode、DocumentTreeNodeActions 和 DocumentTreeContextMenu 组合；需要定制节点操作时，建议直接使用这些导出组件。

BLOCKS

支持的块类型

从写作到知识管理，覆盖常见内容场景，并允许通过插件扩展。

段落H1–H4 标题无序列表有序列表任务列表引用代码块分割线图片附件表格数学公式可折叠标题可折叠列表卡片
块 ID 是稳定引用

每个可寻址节点都有 UUID。Agent、内部链接、撤销和文档索引都应使用 ID，而不是数组下标。

DATA CONTRACT

文档数据

持久化推荐使用规范化后的 Tiptap JSON。Markdown 适合导入导出，不保证所有属性无损。

content.ts
import {
  normalizeEditorContent,
  serializeEditorContent,
} from '@my-notebook/vue-block-editor'

const content = normalizeEditorContent(input)
const stored = serializeEditorContent(content)

schemaVersion

当前文档结构版本。未来版本会被拒绝，避免静默破坏数据。

revision

宿主数据库的乐观锁版本。保存时必须 compare-and-swap。

contentJson

稳定存储 JSON；plainText 用于搜索索引和 Agent 上下文。

AGENT TOOLS

Agent 可以做什么

Agent 不需要操作 DOM。它读取带版本的快照，生成结构化操作，预览后由宿主原子保存。

agent.ts
const tools = createAgentToolAdapter({
  getDocument: (id) => store.get(id),
})

const snapshot = tools.read({ documentId: 'doc-1', revision: 8 })
const hits = tools.search({ documentId: 'doc-1', revision: 8, query: '发布计划' })
const result = tools.validate({
  documentId: 'doc-1', revision: 8,
  operations: [{ type: 'update_attrs', blockId, attrs: { checked: true } }],
})
read读取文档版本、块索引和 JSON
search按块文本和类型搜索
validate试运行操作，不写入数据库
apply返回新的 JSON 和变更块 ID

GUIDANCE

接入时要记住的边界

  • 组件不负责数据库、权限、路由和模型调用。
  • Agent 应使用块 ID，不应依赖数组位置。
  • 保存 Agent 结果时，必须再次检查 revision 并原子提交。
  • 大文档应先 search，再按块读取，避免把整篇文档塞进上下文。
  • 表格当前是文档块，不是完整的数据库视图。
